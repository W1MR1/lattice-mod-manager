Аудит перед 0.4.0. Каждый пункт оценён по трём шкалам от 1 до 5:
**влияние** (насколько мешает работать), **риск** (что будет, если не чинить),
**трудоёмкость**. Приоритет = (влияние + риск) × (6 − трудоёмкость): чем выше,
тем раньше.

## Что сделано в 0.4.0

- **Один договор между окном и главным процессом.** `shared/api.ts` — единственный
  список методов. Главный процесс пропускает только их; типы окна строятся из
  него же; строка `const _methods: readonly (keyof Service)[] = API_METHODS`
  не даст собрать программу, если имя в списке не совпало с методом сервиса.
- **Сервис перестал расти.** Журнал, учёт диска и помощь с Nexus — отдельные
  классы с узким входом (интерфейсы `DiskHost`, `NexusHost`): им видно только
  то, что нужно, и их можно проверять по отдельности.
- **Установщик легче**: шесть языковых пакетов вместо полусотни, 7-Zip только
  для Windows x64.
- **Тесты на GitHub** при каждом изменении.

## План на дальнейшее

1. **0.4.x, вместе с исправлениями:** пункт 4 — каждый присланный отчёт с
   журналом игры превращать в образец для тестов.
2. **0.5.0:** пункт 3 до конца — вынести из сервиса планирование, установку и
   проверку целостности; пункт 7 — тесты окна установки; пункт 5.
3. **Когда появятся средства:** пункт 10.
