## Что из этого следует для Lattice

- **F2 и F3 → движок совместимости.** Те же виды связей (`requires`,
  `recommends`, `conflicts`, `before`/`after`, `provides`), но коллекции тоже
  становятся узлами графа: у коллекции есть `requires`/`conflicts` на другие
  коллекции с диапазонами версий.
- **F4 и F5 → загрузчик без ограничений.** Своего троттлинга нет. Число
  параллельных загрузок и сегментов задаёт пользователь, ничего не привязано к
  платному статусу. Сегменты делятся на лету (work stealing), минимальный
  сегмент 1 МиБ вместо 20 МиБ.
- **F6 → честная граница.** Lattice не обходит серверные ограничения чужих
  сервисов. Без лимитов он качает с источников, которые их не ставят
  (Modrinth CDN, Thunderstore CDN, GitHub Releases, прямые HTTPS-ссылки).
- **F7 → развёртывание** через жёсткие ссылки с откатом на копирование;
  манифест владения файлами и бэкап перезаписанных файлов игры.

## Источники модов (проверено запросами к API 2026-11-04)

- **Modrinth** `api.modrinth.com/v2`: поиск с фасетами (версия игры, загрузчик),
  версии с `dependencies[]` (`required`/`optional`/`incompatible`/`embedded`),
  хэши `sha1`/`sha512`. Сборки — `.mrpack` (`modrinth.index.json`).
- **Thunderstore**: `/c/{community}/api/v1/package-listing-index/` → массив
  ссылок на чанки (JSON, возможно gzip) с полным индексом пакетов и
  зависимостями вида `Namespace-Name-1.2.3`;
  `/api/experimental/package/{ns}/{name}/` — один пакет.
- **GitHub Releases**: `api.github.com/repos/{owner}/{repo}/releases`.

## Что осталось неизвестным

- Поведение Vortex во время работы не наблюдалось (только статический анализ).
- Алгоритм выбора версий в коллекциях Vortex (`versionMatch`) не разбирался
  детально; в Lattice написан собственный решатель.
- Интеграция с Nexus в Lattice сделана через официальные API (GraphQL v2 для
  поиска, файлов и требований, v1 с ключом пользователя для ссылок на
  скачивание) и ссылки `nxm://`. Скачивание с реальным ключом не проверялось:
  ключа на этой машине нет.
